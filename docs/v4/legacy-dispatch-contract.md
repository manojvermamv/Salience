## Implemented boundary

The supported compatibility slice is **no-effects intelligence**, using the existing `IntelligenceLoopWorkflow` and deterministic fixture agents. It does not qualify production intelligence, creative or publication dispatch. Existing paid/effect authorization, general version policy, deployment routing and external recovery obligations remain held.

`LegacyDispatch.submit` reuses `_request_cycle` and `_admit` inside the authenticated PostgreSQL command transaction. The original intent, admission, cycle, frozen context, operation, start outbox, canonical queued intelligence job, immutable job linkage and actor-scoped command response commit together. A failure before commit rolls them back together. Exact commands return their original disposition; changed inputs reject. Manual/event/scheduled requests coalesce by the existing business slot. A coalesced workload must retain the same actor, niche and worker queue. Adoption of an existing fixture cycle requires its untouched original pending start under a row lock; consumed or leased cycles cannot change routes. The job uses the original start trace even when an adoption request has a different trace.

Additive migration `0036_legacy_cycle_dispatch` follows `0035_parallel_agent_teams`. It guards the canonical cycle/context/operation/intent/goal/workspace/program/actor/job binding, command and schedule-plan immutability, and linked job identity. Mutable job state and output remain ordinary canonical projections. Empty rollback is supported; populated dispatch, command or schedule-plan history prevents downgrade.

## Invocation and delivery

Opt-in `V4_LEGACY_DISPATCH_ENABLED=true` requires explicit fixture mode, disabled effects, signed identity configuration and an isolated `V4_LEGACY_FIXTURE_QUEUE` beginning `salience-v4-local-legacy-`. The configured P0 profile keeps legacy dispatch disabled. The compatibility profile replaces the old intelligence router; an old unbound run body is rejected. Other legacy endpoints remain disabled by the signed middleware.

`POST /v1/intelligence/runs` accepts `LegacyIntelligenceDispatch.local.v1` with `goal_id`, a typed canonical `request` containing origin, expected revision, slot and idempotency key, `niche`, and `dry_run=true`. It returns canonical IDs and the committed admission disposition. `GET /v1/intelligence/runs/{job_id}` returns scoped canonical execution and dispatch states. `POST /v1/intelligence/runs/{job_id}/cancel` commits ordinary V4 closure/outbox before a worker signals Temporal. These require current `cycles:write` / `cycles:read` database grants; caller scope headers confer no authority. Reads and cancellation cannot target another workspace or an unlinked job.

`SalienceClient(...).legacy_intelligence` exposes `submit`, `inspect`, `cancel` and `bind_schedule`. CLI commands are `content legacy-intelligence submit --command-json ...`, `inspect`, `cancel --reason ...`, and `bind-schedule --expected-revision ... --niche ...`; they use `SALIENCE_CONTROL_JWT` and the same HTTP transactions.

`python -m salience.cycles.legacy_runtime` requires `TEST_DATABASE_URL`, `TEST_TEMPORAL_TARGET`, `V4_FIXTURE_WORKSPACE`, the isolated queue and explicit no-effects mode. It constructs fixture agents internally. A separate outbox delivery lane keeps the ordinary fixture dispatcher from consuming, exhausting or observing linked legacy starts. Delivery reuses the existing bounded `LocalCycleWorkflow`, inbox ordering, frozen authority, baseline and original permit claim. The intelligence execution ID is `salience-v4-legacy-operation:{operation_id}`; its memo binds the original cycle, operation and job. Every intelligence activity checks current frozen authority, baseline, execution deadline, stop revisions and the original unexpired claimed permit. No model/provider gateway can be injected through this worker constructor.

Start acceptance records handoff, not business completion. Recovery messages retain identity and do not launch another intelligence execution. Unknown acknowledgment or a hard exit between claim/start and acceptance holds the original claim; activity retry cannot issue a second start. This may retain work for operator reconciliation rather than automatically completing it. Cancellation before delivery creates no execution claim or child start; cancellation of an issued execution checks its original runtime type/memo and records control delivery separately from physical cancellation outcome.

## Scheduling and rollback

Prepare the existing one-goal cutover first, then `POST /v1/intelligence/schedules/{goal_id}/bind` with expected revision and niche before activation. The immutable schedule plan pins actor, revision, niche and worker route. Ordinary cutover activation/poll/rollback remains authoritative. Scheduled admission and job materialization share one transaction; polling can recover a committed batch whose admission rolled back. `V4_FIXTURE_AUTOSCHEDULE=1` runs the existing bounded/fair poller. Undelivered outbox, open cycles, nonterminal legacy jobs and unresolved permit liabilities hold rollback.

Optional `V4_LEGACY_TEMPORAL_SCHEDULES=true` uses `TemporalFixtureLegacyScheduleControl` for real **disposable no-effects Temporal schedules**, with an explicitly configured test Temporal target. The fixture schedule row must pin `salience-v4-legacy-fixture:{workspace_id}:{schedule_id}`. Remote action type, payload workspace/program/dry-run, queue and aligned interval must match. Pause precedes activation; remote readback and absence of running actions are mandatory. Recent scheduled actions cannot cross the first V4 slot. Database-only control cannot attest a pinned Temporal schedule. Rollback keeps the canonical fence while recording and reading back a strictly later remote start bound and exact watermark note; unknown outcomes remain fenced for retry.

This is no production cutover authorization. Actual production schedule inventory, supported worker routing/drain, current general policy, real providers, separately authorized remote reconciliation, external alerts and RG0 deployment evidence remain required. Production stays disabled, RG0/RG1 held, P2–P7 gated, optional P6 disabled and main unmerged.
